# LegitBot

Сбор материалов для Nike Air Force 1 Low '07 White / White.
Бот не определяет подлинность. AI, OpenAI, Roboflow, Supabase и база данных
не подключены; новых зависимостей нет.

## Проверка сценария в Telegram

1. /start → «👟 Проверить кроссовки» → Nike → Air Force 1.
2. Выберите «Air Force 1 Low '07 White» и нажмите «Начать проверку».
3. Отправляйте одиночные фотографии по подсказкам. Набор AF1 содержит 13 зон.
4. На шаге 8 снимите стельки сверху. Если они легко вынимаются, можно достать
   их. Если приклеены или не вынимаются, нажмите «Стельки не снимаются».
   Не отклеивайте и не вытягивайте их силой. После нажатия сделайте фото
   сверху внутри обуви. Шаги 9 и 10 будут недоступны, следующий запрос —
   подошва (шаг 11). «Назад» также обходит недоступные зоны.
5. На шаге коробки можно выбрать «У меня нет коробки». Наклейка будет
   отмечена как недоступная, а не как полученная фотография.
6. Обзор показывает реальные количества: «Получено», «Недоступно»,
   «Пропущено», «Требует пересъёмки», а также список проблемных зон.
   Например, при несъёмных стельках и отсутствии коробки: получено 10,
   недоступно 3, пропущено 0, требует пересъёмки 0.
7. «Переснять фото» открывает все 13 зон со статусами. Замена выбранного
   снимка сохраняет остальные. У отсутствующей коробки можно позже добавить
   фото. Зоны под приклеенными стельками остаются недоступными:
   бот не предлагает снимать их силой. Верх стелек переснять можно.
8. «Начать анализ» пока показывает только заглушку. Если есть пропущенные
   снимки или статус «Требует пересъёмки», бот просит исправить их.

На каждом шаге доступны «Назад» и «Отменить проверку».
Фото отправляются по одному, не документом и не альбомом.
Неверные вложения не меняют шаг. Отмена, /cancel и /start очищают проверку.
В меню Nike: Air Force 1, Dunk, Air Jordan, Air Max, Other Nike и «Назад».
Другие линейки и «Другая Air Force 1» показывают сообщение о разработке.
Прежний универсальный сбор 9 фото для остальных брендов сохранён.

## Устройство FSM, статусы и проверка фото

Состояния AF1: выбор модели → подтверждение → фото → обзор → пересъёмка.
MemoryStorage и SimpleEventIsolation сохраняются. В FSM отдельно хранятся
brand, line, model, insole_not_removable и словарь photos по step_id.

Запись содержит step_id, analysis_zone, step_number, file_id, status, reason.
Статусы: received, unavailable, missing, needs_reshoot.
Для двух недоступных ракурсов стелек reason = insole_not_removable;
для коробки reason = no_box. У unavailable нет file_id.
Неотправленная зона считается missing. Пересъёмка заменяет одну запись.
Ни статус received, ни завершение сбора не означают подлинность товара.

PhotoRequirement остаётся переиспользуемым типом. AF1_PHOTO_REQUIREMENTS
и AF1_INSOLE_REMOVAL_ZONES — конфигурация только AF1; вставка AF1 не является
общим требованием для будущих моделей. Будущая модель задаёт собственный набор.

FSM вызывает photo_validation.validate_photo(requirement, photo) до записи
received. Сейчас валидатор возвращает accepted=True без скачивания снимка
и внешних запросов. Интерфейс PhotoValidationResult содержит accepted,
status, reason, user_message. Будущий отказ с needs_reshoot сохраняет
причину, повторяет текущий запрос и не продвигает шаг.

Все данные находятся в памяти. После перезапуска начните заново с /start.

## Что нужно
- Windows и Python 3.12 или новее (при установке включите Add Python to PATH).
- Telegram, токен бота от @BotFather и доступ к интернету.

## Запуск в Windows PowerShell
Если проект находится в длинном служебном пути, сначала скопируйте папку
LegitBot в C:\Projects\LegitBot: это предотвращает ошибку Windows
«слишком длинный путь» при создании окружения.

Откройте папку LegitBot в проводнике, нажмите на адресную строку,
введите powershell и нажмите Enter. Все команды ниже выполняйте
в этом окне по очереди.

1. Создайте отдельное окружение для зависимостей проекта:
   ```powershell
   python -m venv .venv
   ```
2. Установите зависимости:
   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
   Активировать окружение не нужно.
3. В Telegram откройте официальный @BotFather, отправьте /newbot
   и следуйте его подсказкам. Сохраните выданный токен.
4. Создайте локальный файл настроек (один раз):
   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```
   Вставьте токен после TELEGRAM_BOT_TOKEN= и сохраните файл.
   Не отправляйте токен в чат, не публикуйте его и не добавляйте в код.
   Файл .env исключён из Git; .env.example не содержит секретов.
5. Запустите бота:
   ```powershell
   .\.venv\Scripts\python.exe -m legitbot
   ```
6. Откройте своего бота в Telegram и отправьте /start.
   Появятся приветствие и кнопка. Пройдите сценарий выше.

Бот работает, пока открыто окно с запущенной командой.
Для остановки нажмите Ctrl+C. Для повторного запуска повторите только шаг 5.

## Если не запускается
- «Не задан TELEGRAM_BOT_TOKEN»: заполните .env в корне проекта.
- «Неверный формат» или «Telegram отклонил токен»: проверьте токен в .env.
- ModuleNotFoundError: выполните шаг 2 и запускайте Python из .venv.
- Ошибка соединения: проверьте доступ к Telegram и интернету.
- TelegramConflictError: остановите другие экземпляры этого бота.
- Если токен раскрыт, отзовите его через @BotFather и замените в .env.

- legitbot/__main__.py — конфигурация и запуск.
- legitbot/flow.py — общая навигация и прежний сценарий.
- legitbot/af1_flow.py — сбор, обзор и пересъёмка AF1.
- legitbot/photo_requirements.py — конфигурация 13 зон AF1.
- legitbot/photo_records.py — статусы записей и счётчики.
- legitbot/photo_validation.py — интерфейс проверки и локальная заглушка.
- tests/test_flow.py — автоматические проверки.

Токен нужен для проверки реального соединения с Telegram.
Без него можно проверить только код и обработчики локально.

## Автоматические проверки

Из корня проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Используется стандартный unittest, дополнительных зависимостей нет.
Проверяются меню AF1, метаданные 13 зон, отсутствие коробки, пересъёмка каждой
зоны, возврат назад, отмена, неверные вложения, независимость пользователей
и прежний сценарий остальных брендов. Дополнительно проверяются несъёмные
стельки, четыре статуса, пересъёмка и порядок вызова валидатора.
Запросы к Telegram подменены; реальный токен для тестов не нужен.

## Фоновый запуск в Windows

Чтобы бот продолжал работать после завершения временной сессии команд:

```powershell
.\.venv\Scripts\python.exe start_bot.py
```

Запускайте из корня проекта вместо python -m legitbot. Бот работает отдельным
процессом без окна. PID записывается в .runtime/bot.pid, журнал — в
.runtime/bot.log. Повторный запуск при живом записанном PID блокируется.
Не запускайте одновременно фоновый режим и python -m legitbot.

После перезагрузки компьютера запустите снова. Автозапуск не настраивается.
Чтобы перезапустить после изменений, сначала остановите процесс бота по PID
из .runtime/bot.pid в Диспетчере задач, затем повторите команду выше.
Если процесс уже отсутствует, достаточно повторить команду запуска.

Клавиатура Telegram остаётся видимой даже после остановки бота.
Если бот молчит, проверьте процесс и журнал; наличие клавиатуры не подтверждает
работу бота. После перезапуска начните с /start: FSM хранится в памяти.
