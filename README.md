# LegitBot

Сбор материалов для Nike Air Force 1 Low '07 White / White.
Бот не определяет подлинность. AI, OpenAI, Roboflow, Supabase и база данных
не подключены; новые зависимости не добавлены.

## Проверка сценария в Telegram

1. /start → «👟 Проверить кроссовки» → Nike → Air Force 1.
2. Выберите «Air Force 1 Low '07 White» и нажмите «Начать проверку».
3. Отправьте 13 одиночных фото по подсказкам: вид сверху, внешний бок левого
   и правого кроссовка, задники, носовая часть, язычок, внутренняя бирка,
   стельки сверху и снизу, под стелькой, подошва, металлическая вставка AF1,
   наклейка коробки.
4. На каждом шаге доступны «Назад» и «Отменить проверку».
   «Назад» возвращает к предыдущей зоне; новое фото заменяет прежнее.
   На первом шаге возврат ведёт к подтверждению модели.
5. Только на шаге коробки можно выбрать «У меня нет коробки».
   В обзоре будет 12/13 и «Наклейка коробки — отсутствует».
6. В обзоре «Переснять фото» открывает список всех 13 зон.
   Выберите зону, пришлите новый снимок: остальные фото сохранятся,
   бот вернётся к обзору. «Назад» при пересъёмке сохраняет прежний снимок.
7. «Начать анализ» показывает только заглушку о будущем подключении проверки.

Фото отправляются по одному, не документом и не альбомом.
Неверные вложения не меняют шаг. Обязательные ракурсы пропустить нельзя.
Отмена, /cancel и /start очищают текущую проверку.

В меню Nike есть Air Force 1, Dunk, Air Jordan, Air Max, Other Nike и «Назад».
Другие линейки и «Другая Air Force 1» показывают сообщение о разработке.
Прежний универсальный сбор 9 фото для остальных брендов сохранён для
совместимости; он не является специализированной проверкой подлинности.

## Устройство FSM и хранение

Существующие /start, выбор бренда, отмена и MemoryStorage сохранены.
Состояния AF1: выбор модели → подтверждение → фото → обзор → выбор пересъёмки.
Один обработчик фото использует индекс текущей зоны и конфигурацию
PhotoRequirement в photo_requirements.py. У каждой зоны есть id, title,
required, analysis_zone и instruction; правила подлинности не задаются.

В FSM отдельно хранятся brand, line, model и словарь photos по step_id.
Каждая запись содержит step_id, file_id, analysis_zone, step_number, missing.
У отсутствующей BOX_LABEL file_id = None и missing = True.
Пересъёмка заменяет одну запись в словаре. До обзора проверяется комплектность.
Сообщения пользователя обрабатываются последовательно через SimpleEventIsolation.

Данные находятся только в памяти процесса. Снимки на компьютер не скачиваются.
После перезапуска проверки теряются; начните заново с /start.

## Что нужно
- Windows и Python 3.12 или новее (при установке включите Add Python to PATH).
- Telegram, токен бота от @BotFather и доступ к интернету.

## Запуск в Windows PowerShell
Если проект находится в длинном служебном пути, сначала скопируйте папку
LegitBot в C:\Projects\LegitBot: это предотвращает ошибку Windows
«слишком длинный путь» при создании окружения.

Откройте папку LegitBot в проводнике, нажмите на адресную строку,
введите powershell и нажмите Enter. Все команды ниже выполняйте
в этом окне по очереди.

1. Создайте отдельное окружение для зависимостей проекта:
   ```powershell
   python -m venv .venv
   ```
2. Установите зависимости:
   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
   Активировать окружение не нужно.
3. В Telegram откройте официальный @BotFather, отправьте /newbot
   и следуйте его подсказкам. Сохраните выданный токен.
4. Создайте локальный файл настроек (один раз):
   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```
   Вставьте токен после TELEGRAM_BOT_TOKEN= и сохраните файл.
   Не отправляйте токен в чат, не публикуйте его и не добавляйте в код.
   Файл .env исключён из Git; .env.example не содержит секретов.
5. Запустите бота:
   ```powershell
   .\.venv\Scripts\python.exe -m legitbot
   ```
6. Откройте своего бота в Telegram и отправьте /start.
   Появятся приветствие и кнопка. Пройдите сценарий выше.

Бот работает, пока открыто окно с запущенной командой.
Для остановки нажмите Ctrl+C. Для повторного запуска повторите только шаг 5.

## Если не запускается
- «Не задан TELEGRAM_BOT_TOKEN»: заполните .env в корне проекта.
- «Неверный формат» или «Telegram отклонил токен»: проверьте токен в .env.
- ModuleNotFoundError: выполните шаг 2 и запускайте Python из .venv.
- Ошибка соединения: проверьте доступ к Telegram и интернету.
- TelegramConflictError: остановите другие экземпляры этого бота.
- Если токен раскрыт, отзовите его через @BotFather и замените в .env.

## Файлы проекта

- legitbot/__main__.py — конфигурация и запуск.
- legitbot/flow.py — общая навигация и прежний сценарий.

- tests/test_flow.py — автоматические проверки.

Токен нужен для проверки реального соединения с Telegram.
Без него можно проверить только код и обработчики локально.

## Автоматические проверки

Из корня проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Используется стандартный unittest, дополнительных зависимостей нет.
Проверяются меню AF1, метаданные 13 зон, отсутствие коробки, пересъёмка каждой
зоны, возврат назад, отмена, неверные вложения, независимость пользователей
и прежний сценарий остальных брендов.
Запросы к Telegram подменены; реальный токен для тестов не нужен.

## Фоновый запуск в Windows

Чтобы бот продолжал работать после завершения временной сессии команд:

```powershell
.\.venv\Scripts\python.exe start_bot.py
```

Запускайте из корня проекта вместо python -m legitbot. Бот работает отдельным
процессом без окна. PID записывается в .runtime/bot.pid, журнал — в
.runtime/bot.log. Повторный запуск при живом записанном PID блокируется.
Не запускайте одновременно фоновый режим и python -m legitbot.

После перезагрузки компьютера запустите снова. Автозапуск не настраивается.
Чтобы перезапустить после изменений, сначала остановите процесс бота по PID
из .runtime/bot.pid в Диспетчере задач, затем повторите команду выше.
Если процесс уже отсутствует, достаточно повторить команду запуска.

Клавиатура Telegram остаётся видимой даже после остановки бота.
Если бот молчит, проверьте процесс и журнал; наличие клавиатуры не подтверждает
работу бота. После перезапуска начните с /start: FSM хранится в памяти.
